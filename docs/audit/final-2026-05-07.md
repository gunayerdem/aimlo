## 2. NEW issues found during this scan

### NEW-1 (LOW) — `lib/auth-helpers.ts` and `lib/generators.ts` are now orphan modules
The deep-cleanup removed all imports from `app/page.tsx`, and grep across `app/` and `lib/` shows no remaining imports (the only line that touches them is `auth-helpers.ts:3` importing a TYPE from `generators.ts` — circular dead weight). Both files survive ESLint/tsc because they contain valid code, but they're shipped to no one.

- `lib/auth-helpers.ts` exports: `getAuthHeaders`, `isValidFeedback`, `isValidReport`, `upsertProfile`, `checkUsernameAvailable`, `localizeAuthError` — none imported anywhere. Note that `page.tsx` defines its own private `getAuthHeaders` and `isValidReport` at lines 33 and 48 (intentional duplication or oversight unclear).
- `lib/generators.ts` exports `genRoundFeedback` and `genMatchReport` — only `auth-helpers.ts` imports the type, and nothing imports `auth-helpers`.

Risk: bundle bloat + audit confusion (the prompt told us these were "removed", but they are still on disk). Suggested fix: delete both files + the inline duplicate `getAuthHeaders`/`isValidReport` in page.tsx, OR (safer) move page.tsx's private copies into the lib file and re-import. Not blocking ship.

### NEW-2 (MEDIUM) — `tg_handle_new_user` `when others` swallows non-race errors
The trigger fires AFTER INSERT on auth.users. The `when others` clause (lines 40-41 of `0005_followups.sql`) catches **every** non-unique-violation exception and turns it into a `raise warning`. Real failure modes that get swallowed:
- NOT NULL violation on `display_name` (if email is null and `first_name` metadata is also null)
- check constraint failure on the username regex
- FK violation if `profiles.user_id` somehow points at a non-existent user

In any of these, auth.users keeps the new row but `profiles` is empty. The user signs in, lands on the homepage with no profile, and downstream queries that join on `profiles` return empty for them. The app currently has no compensating "create profile if missing" path.

Suggested fix: narrow the catch to a small list of recoverable exceptions, or keep `when others` but log to a `profile_create_failures` table for ops visibility.

### NEW-3 (LOW) — Reality-checker level-3 language detection on mixed strings
`rewriteUnsafeClaims` level-3 sets `isTr` from `/[şçğıöü]|round'da|maç|tur|round'lar/i.test(result)`. If a primarily English AI output happens to contain a single Turkish loan-word from the KB (e.g., "maç" copied from a knowledge file), `isTr` flips true and the level-3 strip injects "bu round'da" into an otherwise English string.

Inversely: a Turkish output where the only non-stripped tokens lack diacritics (e.g., entirely written in basic Latin: "bu kez") would be classified `isTr=false` and get "this round" injected.

Severity: low — level-3 is the rarest path (means count + position + repetition all overclaimed simultaneously) and the result is cosmetic (one stray phrase, not a safety violation). But worth a follow-up: detect language from the original `text`, not the post-strip `result`.

### NEW-4 (informational) — knowledge-loader has a non-cached `existsSync`
`getAgentFile` (lines 122-135) does `fs.existsSync(perAgentFull)` to decide whether to return the path. This existsSync is NOT memoized — it runs on every call before the cache helps. Cost is small (~µs each), but if you wanted full cache benefit, wrap the per-agent-file decision in the same map. Not a regression vs. pre-cleanup; calling out for thoroughness.

### Items A-H from the audit prompt — short answers

- **A.** No lingering references to deleted components anywhere (grepped `app/`, `lib/`, `components/`).
- **B.** No deleted imports re-introduced. `MAPS`, `SCORE_OPTIONS`, `AGENT_GROUPS`, `AGENT_GROUP_LABELS`, `isValidFeedback`, `upsertProfile`, `checkUsernameAvailable` not imported anywhere in app code.
- **C.** Atomic merge SQL: `security definer` + `set search_path = public` + revoke-all + grant-only-to-service_role is the correct hardening pattern. Passes standard checks. One gap: function does not validate `p_patch` size, so a service-role caller could pass a huge JSONB. Acceptable since service-role is internal.
- **D.** See NEW-2 above. The exception block does NOT only swallow `unique_violation` — it also has `when others` that swallows everything else as a warning. Real concern.
- **E.** The cache prevents repeated reads correctly. Race: in a serverless instance two concurrent requests COULD both miss and both call `fs.readFileSync`, then both set the same key. The reads are independent and the second `set` overwrites with identical content, so no correctness bug — just one wasted read on cold start. Standard JS single-threaded event loop bounds this further. No fix needed.
- **F.** See NEW-3 above. The regex works but mis-classifies mixed-language strings.
- **G.** `ready` is computed each render from `confirmText`. The hidden input's `value` reflects current `ready`. The submit button is `disabled={!ready || pending}`. Race: user types "SİL" → ready=true, submit enabled, hidden=SİL. User immediately backspaces while clicking submit — React batches state, the form action receives the FormData snapshot at submit time. No race observed; the disabled state and the hidden value share the same render cycle.
- **H.** `?verified=true&deleted=1`: the effect's if/else if/else if checks `verified === "true"` first, so it shows the success banner and never sees `deleted`. This URL is not produced by any internal redirect (delete → `/?deleted=1` only; verify → `/?verified=true` only). Theoretical only. Not a bug.

## 3. Accepted risks still standing

Carried over from prior rounds, none re-introduced or worsened by this cleanup:

- **Player-memory atomic merge** — RPC exists in DB but `lib/player-memory.ts` still uses the read-modify-write JS path. The DB function is available for a future targeted refactor; today the lost-update race is reduced (single serverless instance, single in-flight match-end per user is the common case) but not eliminated.
- **Login enumeration via timing** — server response times for "no such user", "wrong password", and "right password but unverified" should be padded to a common floor. Wave 4 added a partial timing pad; verifying it's still in place was out of scope here.
- **Reality-checker** — only catches numeric and position overclaims; doesn't validate factual claims about agent abilities or map callouts.
